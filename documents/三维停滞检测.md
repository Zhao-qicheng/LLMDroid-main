# 三维停滞检测

---

## 一、论文宏观思路

### 1.1 问题动机（Motivation）

LLMDroid 在 EXPLORE 阶段用 **代码覆盖率增长率** 作为唯一信号触发 LLM GUIDE。这存在三类盲区：

| 盲区                 | 现象                   | 后果                                    |
| ------------------ | -------------------- | ------------------------------------- |
| **信号单一**           | 仅 Code 维判停           | UI 仍在有效探索时过早 GUIDE，或 UI 已空转时 GUIDE 过晚 |
| **UI–Code 分歧（B3）** | Code 仍涨，但 UTG 无新有效转移 | 贪婪探索在重复无效动作，LLM 介入延迟                  |
| **探索质量不可见**        | 无效点击、同页空转无度量         | 无法区分「真停滞」与「低质量空转」                     |

**核心论点**：代码覆盖率反映 **程序执行**，UTG 反映 **UI 探索**；二者不同步时，单一 Code 信号不足以决定何时请求 LLM 指导。

---

### 1.2 方法概览（Method Overview）

提出 **三维联合停滞检测（CSW-SD, Code–State–Widget Stagnation Detection）**：

在每次 EXPLORE 步后，从三个互补维度观测探索进展：

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  Code 维    │   │  State 维   │   │  Widget 维  │
│ 覆盖率增长  │   │ 有效UI转移  │   │ 局部+质量   │
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │                 │                 │
       └─────────────────┼─────────────────┘
                         ▼
              should_trigger_guide()
                         │
              True → ASK_GUIDANCE → NAVIGATE → GUIDE
              False → 继续 UTG Greedy EXPLORE
```

**设计原则**：

1. **最小侵入**：只读 UTG 已有字段（`transitions`、`is_event_explored`），不改 DroidBot 探索核心。
2. **与 Code Monitor 同契约**：State/Widget 也要求 **窗口满 W 才判停**，避免预热期误触发。
3. **联合决策而非加权求和**：用显式规则处理 Code–UI 分歧，可解释、可消融。

---

### 1.4 GUIDE 触发策略（Decision Policy）

| 规则     | 条件                                                       | 动作          | 论文对应             |
| ------ | -------------------------------------------------------- | ----------- | ---------------- |
| **1**  | `code_ready ∧ code_stalled ∧ state_stalled`              | GUIDE       | 全局探索枯竭           |
| **2**  | `code_ready ∧ code_active ∧ state_stalled`               | GUIDE       | B3：UI–Code 分歧    |
| **3**  | `ready ∧ widget_stalled ∧ r_invalid > r_thresh`          | GUIDE       | 局部控件耗尽后的低质量空转    |
| **4**  | `code_ready ∧ code_stalled ∧ ¬state_stalled`             | **不** GUIDE | UI 仍有有效转移，抑制过早触发 |
| **默认** | 其他                                                       | 不 GUIDE     | 继续 EXPLORE       |

**与 baseline 关系**：去掉 State/Widget（仅 R1 中 \(S_{state}\) 恒为 0、去掉 R2–R4）≈ 原 LLMDroid Code-only 触发。

**规则顺序说明**：R3 不再依赖 `state_stalled`，否则它会被 R1/R2 完全覆盖，无法体现 Widget 维的独立作用。R3 表达的是「当前页可探索控件已经基本耗尽，同时最近窗口大多是同页空转」，即使窗口内偶尔仍存在有效状态跳转，也可以认为贪婪探索质量已经下降，适合请求 LLM 重新选择目标。

**Code 预热说明**：`check_low_growth_rate()` 在覆盖率窗口未满时也会返回 `False`，因此不能把 `¬code_stalled` 直接解释为「代码仍活跃」。本文显式区分 `code_ready` 与 `code_active`：只有覆盖率窗口已满，且未判定为低增长时，才认为 `code_active=True`。

### 1.6 在 LLMDroid 流水线中的位置

```
EXPLORE (UtgGreedySearchPolicy)
    │ 每步
    ▼
__update_utg() → transitions 更新
__switch_mode() → update_code_coverage()
                → should_trigger_guide()  ← CSW-SD
    │
    ├─ False → 继续 EXPLORE
    └─ True  → ASK_GUIDANCE → NAVIGATE → GUIDE (LLM)
```

CSW-SD **只改触发时机**，不改 OVERVIEW / GUIDE / TEST 的 LLM 逻辑。

### 2.7 `should_trigger_guide` — 总决策函数

```python
def should_trigger_guide(
    utg: "UTG",
    cv_monitor: "CodeCoverageMonitor",
    current_state: "DeviceState",
    window: int = 80,
    eps_state: int = 0,
    eps_widget: float = 0.05,
    r_thresh: float = 0.7,
) -> bool:
    # Code 维
    code_stalled = cv_monitor.check_low_growth_rate()
    code_ready = cv_monitor.growth_window_ready()
    recent_gr = cv_monitor.recent_gr()
    code_active = code_ready and (not code_stalled)

    # 窗口就绪
    ready = window_ready(utg.transitions, window)

    # State 维
    delta_e_eff = count_effective_in_window(utg.transitions, window)
    state_stalled = ready and (delta_e_eff <= eps_state)

    # Widget 维
    u_local = local_unexplored_ratio(utg, current_state)
    widget_stalled = ready and (u_local < eps_widget)
    r_invalid = (
        invalid_ratio_in_window(utg.transitions, window) if ready else 0.0
    )

    log_stagnation_stats(
        code_ready=code_ready,
        code_stalled=code_stalled,
        code_active=code_active,
        state_stalled=state_stalled,
        delta_e_eff=delta_e_eff,
        u_local=u_local,
        r_invalid=r_invalid,
        widget_stalled=widget_stalled,
        ready=ready,
    )
    # R1：双停
    if code_ready and code_stalled and state_stalled:
        return True
    # R2：B3 分歧
    if code_ready and code_active and state_stalled:
        return True
    # R3：Widget 枯竭 + 低质量空转
    if ready and widget_stalled and r_invalid > r_thresh:
        return True
    # R4：抑制过早 GUIDE
    if code_ready and code_stalled and not state_stalled:
        return False
    return False
```

**`window` 建议**：与 Code `wsize` 对齐（AndroLog 80 / Jacoco 60），论文中写「统一窗口 W」。

## 二、子函数实现（对应你的完善版设计）-

### 2.1 `window_ready`

**论文角色**：与 Code Monitor 预热契约对齐。

```python
def window_ready(transitions: Sequence[Transition], window: int) -> bool:
    """|transitions| >= window 时才允许判 State/Widget 停滞。"""
    return window > 0 and len(transitions) >= window
```

---

### 2.2 `count_effective_in_window` — State 维

**论文角色**：计算 \(\Delta E_{eff}\)。

```python
def count_effective_in_window(
    transitions: Sequence[Transition], window: int
) -> int:
    if window <= 0 or not transitions:
        return 0
    recent = transitions[-window:]
    return sum(
        1
        for old_state, _event, new_state in recent
        if old_state is not None
        and new_state is not None
        and old_state.state_str != new_state.state_str
    )
```

**实现要点**：

- 与 `utg.add_transition()` 中 `state_str` 相等/不等判定一致。
- 无效转移也在 `transitions` 中，必须逐步比较，不能读 `effective_event_strs` 的 set 大小。

---

### 2.3 `local_unexplored_ratio` — Widget 维（局部）

**论文角色**：计算 \(u_{local}\)（当前页快照），用于判断当前页控件是否基本耗尽，并参与 R3。

```python
def local_unexplored_ratio(utg: "UTG", state: "DeviceState") -> float:
    possible = state.get_possible_input()
    if not possible:
        return 0.0
    explored = sum(
        1 for event in possible if utg.is_event_explored(event, state)
    )
    return 1.0 - explored / len(possible)
```

**实现要点**：

- `is_event_explored` 查 `effective_event_strs ∪ ineffective_event_strs`。
- `widget_stalled` 需要与窗口就绪条件绑定，即 `ready and u_local < eps_widget`，避免探索初期当前页控件很少时误触发。
- 默认策略中 `widget_stalled` 与 `r_invalid` 共同构成 R3，使 Widget 维不只作为日志指标。

---

### 2.4 `invalid_ratio_in_window` — Widget 维（质量）

**论文角色**：计算 \(r_{invalid}\)。

```python
def invalid_ratio_in_window(
    transitions: Sequence[Transition], window: int
) -> float:
    if window <= 0 or not transitions:
        return 0.0
    recent = transitions[-window:]
    invalid = sum(
        1
        for old_state, _event, new_state in recent
        if old_state is not None
        and new_state is not None
        and old_state.state_str == new_state.state_str
    )
    return invalid / len(recent)
```

**实现要点**：

- 分母是 `len(recent)`，满窗时等于 W。
- 仅在 `ready=True` 时参与规则 3。
- R3 不再要求 `state_stalled=True`，否则会被 R1/R2 覆盖；它刻画的是当前页控件耗尽后的同页空转质量问题。

---

### 2.5 `growth_window_ready` / `recent_gr` — Code 维状态（在 `base_monitor.py`）

**论文角色**：区分覆盖率窗口是否已经完成预热，避免把「尚未判停」误解释为「代码仍活跃」。

```python
def growth_window_ready(self) -> bool:
    return len(self.__gr_to_check) == self.__WINDOW_SIZE

def recent_gr(self) -> float:
    if not self.__gr_to_check:
        return 0.0
    return self.__gr_to_check[-1]
```

**调用顺序**：必须先 `check_low_growth_rate()`（内含 `__update`），再读 `growth_window_ready()` 与 `recent_gr()`。

**语义约束**：

- `code_stalled=True`：覆盖率窗口已满，且窗口内增长均低于动态阈值。
- `code_ready=True`：覆盖率增长窗口已满，可以安全解释 Code 维状态。
- `code_active=True`：`code_ready and not code_stalled`，表示 Code 维在已预热后仍未停滞。
- `code_ready=False` 时，`code_active` 必须为 `False`，不参与 B3 分歧触发。

### 2.6 `log_stagnation_stats` — 实验对齐

```python
def log_stagnation_stats(
    code_ready: bool,
    code_stalled: bool,
    code_active: bool,
    state_stalled: bool,
    delta_e_eff: int,
    u_local: float,
    r_invalid: float,
    widget_stalled: bool,
    ready: bool,
):
    logger.info(
        "[CSW-SD] ready=%s code_ready=%s code_stalled=%s "
        "code_active=%s state_stalled=%s delta_e_eff=%d u_local=%.3f "
        "r_invalid=%.3f widget_stalled=%s",
        ready, code_ready, code_stalled, code_active, state_stalled,
        delta_e_eff, u_local, r_invalid, widget_stalled,
    )
```

**`window` 建议**：与 Code `wsize` 对齐（AndroLog 80 / Jacoco 60），论文中写「统一窗口 W」。
